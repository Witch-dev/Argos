# Modern web platform adoption

Source of guidance: GoogleChrome/modern-web-guidance (agent guides for current web platform APIs). Goal: replace hand-built patterns in `Apollon/web/src` with native ones where the browser now does the job, without changing how anything looks or behaves.

Status: scanned 2026-11-18 by read-only search (the guide's own `legacy-scan` CLI was blocked by the permission classifier; run it by hand if wanted: `npx modern-web-guidance@latest legacy-scan src` in `web/`). Nothing changed yet.

## Already modern (leave alone)
React 19, Vite 8, TS 6. `:has()` (16 files), container/media queries, `clamp()`, `aspect-ratio`, `dvh/svh`, `text-wrap`, CSS nesting, `color-mix/oklch`, `prefers-reduced-motion` (15 files), rem-only font sizes, `loading="lazy"`, passive scroll listeners, `isComposing` on Enter-to-submit. No moment/date-fns.

## Scan findings

| Area | Finding | Native replacement |
|---|---|---|
| Modals | 12 files with hand-built `role="dialog"`/`aria-modal` (`Modal.tsx` portal + AvatarPicker, ChallengeDialog, ConfirmBookModal, CreateClubModal, EmailConfirmation, ImportDialogs, ProgressUpdateModal, StoryViewer, WritingComposerModal, WritingDetailModal); ~24 files handle Escape by hand; no body scroll lock found | `<dialog>` + `showModal()`: focus trap, Esc, top layer, inert background, `::backdrop`, `closedby` light-dismiss |
| Menus/popovers | OverflowMenu, ThemeMenu, NotificationBell, EmojiPicker, ChatReactions, HeaderSearch, AnnotatableText popover: JS open state, Escape and outside-click handlers, `getBoundingClientRect` in HeaderSearch | `popover` attribute + `popovertarget`/invoker commands; CSS anchor positioning |
| Validation | 32 uses of manual `aria-invalid`/touched/error state; no `:user-invalid` | `:user-invalid`/`:user-valid` for styling, keep `aria-invalid` synced |
| Forms | 4 email inputs missing `autoComplete` (ForgotPassword, Register, RequestInvite, AccountSettings); 10 custom `role=switch/checkbox/radio/tab/menu/listbox` | `autocomplete` tokens; native `<input type=checkbox switch>`; native controls styled with `accent-color`/`appearance` |
| Textarea | no `field-sizing` except 1 file | `field-sizing: content` + min/max |
| Motion | 12 `setTimeout` (some animation/state timing); no `@starting-style`, view transitions, `interpolate-size` | `@starting-style` + `transition-behavior: allow-discrete` for enter/exit; same-document view transitions for route changes; `interpolate-size: allow-keywords` for height auto |
| Responsive | 123 of ~133 media queries are one `max-width: 640px` hard breakpoint; 6 JS `matchMedia` reads (NotificationBell, Feedback, Shelf, ShareButton, ClubChat) | container queries where a component sizes by its parent; keep viewport query for page chrome; JS only when state needs it |
| Theming | 5 themes via tokens, no `@layer`, no `light-dark()`, no `@property` | `@layer` (reset, tokens, components, utilities) to stop specificity fights (3 `!important` left); `@property` for animatable tokens |
| Performance | no `fetchpriority` on LCP/cover images, `<img>` often without width/height, no `content-visibility`, no `scheduler.yield` | `fetchpriority="high"` on the first cover, explicit dimensions, `content-visibility: auto` on long lists/feed cards, `scheduler.yield()` in long handlers (CSV import) |
| Dates | 73 `new Date`/`Date.now` uses, `Intl` in 14 files | keep `Intl`; `Temporal` only behind a feature check, later |
| URLs | `startsWith('https://')` (MeetingForm), `pathname.split('/')` (useSection) | `new URL()` parsing for the link check |
| Scroll | JS scroll listeners in ActivityStrip, Shelf, Feedback (show/hide on scroll) | scroll-driven animations / scroll-state container queries where supported |
| Security | 1 `innerHTML`/`dangerouslySetInnerHTML` use | review with `argos-security`; Sanitizer API or Trusted Types if the input is not fully ours |

## Rules for every task below
- Check browser support on MDN/Baseline before each item. Use only "Baseline widely/newly available" features, or add a fallback and `@supports`. Anchor positioning, `closedby`, invoker commands, `field-sizing`, scroll-state queries are the ones to check first.
- No visual change unless the design critique round says otherwise. Run `web-design` screenshot round for visual phases.
- jsdom has no `<dialog>.showModal()`; stub it in test setup once, not per test.
- Update the five locale files only if text changes (it should not).
- Review after each phase (`reviewer`; `argos-security` for the innerHTML item).

### Phase 2: modals to `<dialog>` (done 2026-11-18)
- [x] Rewrite `Modal.tsx` on `<dialog>` + `showModal()`; props kept (plus optional `label`, `frameClassName`, `cardClassName`, `initialFocus="card"`), so its 10 existing users didn't change. Removed: the hand-written focus trap and the window Escape listener (there was no scroll lock). **Portal kept on purpose:** without it a modal opened inside a `<form>`, a link card or a menu would sit inside that element's HTML (invalid nested forms, the link's click, its inherited styles, a `display: none` parent hiding it)
  - The `<dialog>` is the transparent full-screen frame (scrolls, takes outside clicks) and the card a `<div>` inside it, so the geometry is unchanged. Base styles sit in `:where()` so a caller's class always wins
  - Escape: the browser's `cancel` → the parent unmounts it. `cancel`/`close` are filtered to the dialog's own (React bubbles them through its tree, which closed both of two stacked dialogs)
  - Outside click stays in our code: `closedby` has limited support (MDN, 2026-11-18)
  - Focus: `autoFocus` inside is kept (the closed dialog is laid out invisibly so React can focus it; remembered through StrictMode's double run), else the first control, without scrolling; back to the opener on close; to the card when the focused control disappears (a step change)
- [x] Moved the hand-built dialogs onto it: AvatarPicker, ConfirmBookModal, CreateClubModal, EmailNotConfirmedDialog, ImportDialogs, ProgressUpdateModal, WritingComposerModal, WritingDetailModal (overlay mode), StoryViewer (its draft-Escape is now a capture listener that cancels the key). **ChallengeDialog left as is:** it's an inline panel on the list page, not a modal
- [x] jsdom stub in `test/setup.ts` (`showModal`/`close`, Escape → `cancel` on the topmost dialog unless a handler prevented it); `Modal.test.tsx` added; Tab-trap assertion removed from ReportDialog's test (the browser's job now)
- [x] `::backdrop` uses `--scrim`; entrance with `@starting-style` (fade + 8px rise, `--duration-state`), exit 120ms (`--duration-feedback`, `--ease-in`) only for Esc/outside click (a caller's own button unmounts it at once); reduced motion drops the movement. `@starting-style` is Baseline newly available; without it the dialog just appears
- [x] Browser-check 2026-11-18 at 1280 and 375: open, Esc, focus return, outside click, inert page, nested (Report over a writing, Share card over progress), story viewer keys, mobile keyboard, 5 themes (Create club, Report), reduced motion. Design critique: nothing to fix. Not reached: the import search dialog
- [x] Reviewer: fixed a dialog left invisible over an inert page when the parent doesn't close it (a writing overlay with no history to go back to), the exit timer not cleared on unmount, a closed-but-mounted dialog still in the tab order, and the story viewer's keys acting when another dialog is on top. The jsdom stub's `close` event is now queued as in browsers

Browsers without `popover` at all (Safari before 17, 2023) get menus that don't open: accepted, as it is widely available.

### Phase 4: forms (done 2026-11-22)
Support checked 2026-11-22: `:user-invalid`/`:user-valid` Baseline widely available (since November 2023 + 30 months); `:is()` is forgiving, so a browser without it still gets the `[aria-invalid]` half. The `switch` attribute on a checkbox is Safari-only, not used.
- [x] One rule in `index.css` for every field in error: `:user-invalid` (breaks its own `required`/`type`/`min` rule after the reader typed and left it, or after a submit; never on a fresh form) or `[aria-invalid='true']` gets a 1px `--danger` outline over its border (6.4:1 on the field in Dark, 6.7:1 in Paper); the green focus ring replaces it while focused. An outline, not `border-color`: each component draws its border with a selector a global rule can't outweigh. The six per-module `[aria-invalid]` border rules removed (ClubChat keeps its own 2px one); fields that set `aria-invalid` with no visual before (Register/username, Suggest, Club settings, Story reply, admin queue) now get the edge. `:user-valid` not styled: a green "correct" mark on every field would be noise
- [x] Errors before interaction: none found. Every page-set error appears after a submit, the ISBN typo only on a complete number
- [x] `lib/userInvalid.ts` keeps `aria-invalid` in step with `:user-invalid` (document capture listeners: input, change, focusout, invalid; whole form after submit and reset). **Ownership rule:** a component that sets `aria-invalid` always passes a boolean (13 `x ? true : undefined` turned into `Boolean(x)`), so the attribute is there from the first render and the listener never writes on that field; the CSS then ignores `:user-invalid` on an `aria-invalid="false"` field, so screen and screen reader agree. A form that stays open after a save and is emptied by code should call `form.reset()` (none does today: they all close), or a required field would keep its edge
- [x] The 10 custom widgets: Pages/Chapters in `CheckpointFields` (role=radio buttons) → two native radios in labels, same look, now with arrow keys and one Tab stop. Already native: `Switch` (checkbox + `role="switch"`), ConfirmBookModal's suggestion list (radios). Not form controls, kept: the two `role="menu"` menus (Phase 3), HeaderSearch's listbox (combobox), four tablists (no native tabs). `Segmented` (28 uses, `aria-pressed` buttons) left as is: making it radios changes keyboard behaviour app-wide, a design decision of its own
- [x] Reviewer: fixed the listener clearing a component's own `aria-invalid="true"` (the ownership rule above) and syncing on submit (found in the browser check). Kept: TagInput's `.box input:focus { outline: none }` hides the edge in the rare focused-but-not-focus-visible case; `:user-invalid` with no text beside it on `noValidate` forms until submit (design critique: add messages where missing; see `bugs/login-empty-submit-raw-server-text.md` for the auth forms)
- [x] `lib/userInvalid.test.ts` added
- [x] Browser-check 2026-11-22 at 1280 and 375, Paper and Dark, Chromium plus Firefox and WebKit: fresh forms clean, email edge and `aria-invalid` on leave, green ring when focused, cleared when fixed, taken username, empty login submit, reading goal, Pages/Chapters by mouse and arrow keys, privacy switch. ### Phase 5: CSS architecture and motion (done 2026-11-22)
Support checked on MDN 2026-11-22: `@starting-style` newly available (August 2024), same-document view transitions newly available (October 2025), scroll-driven animations newly available (October 2026), `interpolate-size` limited (Chromium only), scroll-state queries not Baseline. Size container queries widely available.
- [x] `@layer reset, tokens, base` in `index.css`. **Only the floor is layered:** element-level defaults, the popover reset, tokens and themes, headings, selection, caret, the focus ring, press feedback. Any component class already beat them, so nothing moves. **Unlayered on purpose:** `a:hover`, the `.btn` family, the danger edge, the utilities and motion classes. CSS modules are unlayered, and unlayered beats every layer whatever its specificity: layering `a:hover` would take the hover colour off 58 links styled by a module, and layering `.btn` would let a component's plain class beat a button's hover and pressed states. Checked that no CSS loads before `index.css` (nothing in `AuthContext`'s import graph), and that the minifier keeps the order
- [x] The `!important`s (6, not 3: four in `index.css`, one each in Shelf and BookDetailPage) removed with the blanket reduced-motion rule. Every transition and animation but four takes its length from the duration tokens, so reduced motion now sets the tokens (feedback, state, panel 0ms; focal 150ms, the settling cover's fade). The four (LoadingBar's two, Skeleton's pulse, Layout's page fade) stop in their own stylesheets, and GoalBar and MemberProgressBar (a transform on `--duration-focal`) too. The loading line under reduced motion is now a still full-width line; the blanket rule had made its runner flicker
- [x] **Verified unchanged:** an in-browser A/B swapping the old and new `index.css` on the same page, 8 routes (styleguide, home, book, author, profile, settings, clubs, stats): 0 computed-style differences on 4,969 elements (all properties) and on 1,725 links, buttons and fields forced into `:hover`, `:active` and `:focus-visible`, with and without reduced motion
- [x] Container queries: **StatTiles only** (a `.box` with `container-type: inline-size`, `@container (max-width: 36rem)`), the one piece that sits in boxes of very different widths. In the right rail's year card the tiles now pair up under the lead number instead of stacking (design critique: better, ship). Kept on the 640px query: Card, ThreadCard, WritingCard padding and ReaderCard wrapping (only ever in the page column, whose width is the screen's), Shelf's cover size (deliberately "three to a shelf on a phone") and its arrows (a pointer matter). ClubChat has no width rules; it already sizes by its parent (dock or page)
- [x] Menus on the popover get an entrance (`@starting-style`: fade plus `scale` 0.97 → 1, `--duration-state`), measured in Chromium, Firefox and WebKit; under reduced motion they open at once. `scale`, not `transform`, so a panel's own transform is untouched. No exit: contents unmount on close (Phase 3), so a fade out would show an empty box
- [-] Toasts: `ActionNote` already fades in on mount with `motion-fade`; `@starting-style` would do the same. Banners: the email-confirm banner shows on page load, and DESIGN.md allows no load choreography
- [-] `interpolate-size` for expanding sections: DESIGN.md forbids animating height, and it is Chromium-only
- [-] View transitions for route changes: DESIGN.md rejected page-level effects (the page turn, 2026-10-13); the 150ms page fade already does the job
- [-] JS `matchMedia` in NotificationBell and Feedback kept: both already style in CSS. The bell's check decides what a click does (panel or the /notifications page), which CSS can't, short of rendering two controls; Feedback's check stops a re-render on every desktop scroll. A scroll direction and the "comes back when you stop" timer can't be done in CSS either
- [-] Scroll-state queries for the Shelf and ActivityStrip arrows: not Baseline, so the JS would stay for Firefox and Safari, two mechanisms for one job. Found instead: ActivityStrip's and ClubPage's smooth scrolls ignored reduced motion (the old `scroll-behavior` override never reached `scrollBy`); `lib/motion.ts` `scrollBehavior()` now used there, in ClubChat's scroll to the newest message, and in place of the hand-written checks in Shelf, LandingPage, ListDetailPage and ProfilePage
- [x] Fixed on the way: ClubChat's "new messages" button jumped half its width while pressed (the shared `.btn` press transform replaced its centring transform); it centres with `translate` now
- [x] Fixed after the phase: the feedback button stopped hiding while a dialog is open (its rule looked for `aria-modal`, which the native `<dialog>` of Phase 2 doesn't set; now `dialog:modal`). The language picker under a review or writing kept its small text on a phone, so iOS zoomed the page when it opened (its own class beat index.css's 16px rule for selects); 16px on a phone now. Both checked in the browser
- [x] Reviewer: no bugs. Fixed its two low findings (ClubChat's smooth scrolls ignored reduced motion; three pages had their own copy of the check, now `scrollBehavior()`). Confirmed: no raw duration missed, delays unchanged, Modal's exit timer reads the computed duration, `animationend` still fires on the settling cover, no popover panel sets its own transition/opacity/scale, every StatTiles placement stretches the box (none can collapse)
